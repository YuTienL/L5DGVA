## 5. Five Constitutional Dimensions

### P1 --- LOCATION_INDEPENDENT

Support copy/clone/move/rename/extract, different users/paths, Windows
bootstrap, WSL2 and Docker-mounted runtime. No runtime dependence on
absolute bootstrap path, basename, username, gateway host, remote EDA
host or personal Obsidian Vault path. Host/environment identities belong
in profiles/configuration. Local repo root and remote EDA workdir are
distinct.

### P2 --- EVIDENCE_GROUNDED

Preserve stronger existing evidence hierarchy. Conceptually: Hypothesis
→ Evidence → Confidence → Validation → Action. AI inference alone is
insufficient; uncertainty remains explicit.

### P3 --- KNOWLEDGE_DRIVEN

Where supported, retrieve/evaluate applicable
KC/M1--M5/Obsidian/research/project knowledge before important
generation/debug/RCA/coverage/signoff decisions. Stored knowledge is not
operational until Retrieval → Applicability Validation → Agent
Consumption → Decision/Action Impact → Recorded Evidence.

### P4 --- CONTINUOUS_EVOLUTION

External: Research/Paper/New Technology → Intelligence → Distillation →
Evidence/Provenance → Applicability → Capability Candidate →
Experiment/Validation → Capability Evolution. Internal: User/Project →
Generation/Simulation/Debug/RCA/Regression/Coverage/Signoff → Experience
Extraction → Evidence → Applicability/Generalization → Promotion →
Capability Evolution. One project observation must not silently become a
universal rule.

### P5 --- END_TO_END_DV_ALIGNMENT

OpenSpec Intake → DV Knowledge Retrieval → Discovery → Minimal
Structured Clarification → vPlan → VIP/UVM Generation →
Sequence/Scenario/Firmware → Checker/Scoreboard/Assertion → Build/Smoke
→ Local/Remote EDA Execution → Regression → RCA/Debug → Functional
Coverage Analysis → Coverage-Hole Closure → Requirements/Evidence
Traceability → Waiver Handling → SIGNOFF_READY → Signoff → Experience
Consolidation → COMPLETE.
