## 7. Redundant Question and Role Routing Qualification

If high-confidence/validated evidence already establishes a field,
asking the user again without policy reason is
`REDUNDANT_HUMAN_QUESTION`. RCA may identify discovery-not-run,
result-not-consumed, mapping gap, validation ignored, question-policy
defect or stale context.

Verify question owners: DESIGN→DE, VERIFICATION→DV, genuine
SHARED→DE+DV. Track WRONG_QUESTION_OWNER, UNROUTABLE_QUESTION,
LAZY_SHARED_CLASSIFICATION. SHARED is not an uncertainty fallback.

## 8. USB-Specific vs Generic KC

Classify KC applicability at least as USB_SPECIFIC, PROTOCOL_CLASS,
GENERIC_DV, PROJECT_SPECIFIC. USB observations must not automatically
become universal rules. Generic promotion requires applicability and
counterexample evidence.

## 9. Gap Taxonomy and RCA

Define/reuse taxonomy equivalent to MISSING_REQUIRED_FIELD,
INCORRECT_VALUE, MISSING_EVIDENCE, WRONG_DERIVATION,
DISCOVERY_NOT_CONSUMED, REDUNDANT_HUMAN_QUESTION, WRONG_QUESTION_OWNER,
MISSING_VPLAN_ITEM, MISSING_TOPOLOGY_ITEM, MISSING_COVERAGE_LINK,
MISSING_SIGNOFF_EVIDENCE, ROUND_TRIP_LOSS, STALE_WORKBOOK_FAILURE,
CONFLICT_NOT_DETECTED, SCHEMA_DEFECT, PRESENTATION_ONLY_DEFECT,
USB_SPECIFIC_KNOWLEDGE_GAP, GENERIC_DV_KNOWLEDGE_GAP.

GENERATOR_DEFECT, FIELD_MAPPING_DEFECT, CANONICAL_MODEL_GAP,

USER_INPUT_REQUIRED, UX_PRESENTATION_DEFECT. Software defects become
implementation issues, not knowledge rules.

qualification/workbook/field/gap/RCA/applicability/promotion provenance.

KC. Retrieved-but-ignored is not learning success.
