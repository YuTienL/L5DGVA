## Legal drop conditions

A scoreboard may suppress a missing-transaction mismatch ONLY when one of these
documented conditions holds. Each is checkable via
`design_intent.is_drop_legal(doc, condition_id, mode)`.

| ID | Applies when | Mode | Description | Basis |
| --- | --- | --- | --- | --- |
| `DROP-001` | state == SUSPEND at the time the packet arrives | all | A packet received while the controller is in SUSPEND is discarded without error. The scoreboard must not report a missing transaction. | DEMO Controller Databook §4.3 Suspend |
| `DROP-002` | mode == low_power and rx_fifo_full asserted on arrival | low_power | In low_power mode a packet arriving while the RX FIFO is full is dropped rather than backpressured. | DEMO Controller Databook §3.2 Low Power |

## Backpressure conditions

These relax TIMING expectations only. A stalled transaction must still arrive
intact -- none of these may be used to excuse a content mismatch.

| ID | Applies when | Mode | Description | Basis |
| --- | --- | --- | --- | --- |
| `BP-001` | mode == high_speed and rx_fifo_full asserted | high_speed | In high_speed mode a full RX FIFO causes backpressure, not a drop. The transaction is delayed but must still arrive intact. | DEMO Controller Databook §5.1 Flow Control |

## Ordering rules

| per endpoint | `strict_in_order` | DEMO Controller Databook §5.2 Ordering | Packets on a single endpoint are delivered in the order received. |

A scope absent from this table resolves to `UNKNOWN` via
`design_intent.scoreboard_compare_mode()`, whose safe default is the STRICTER
